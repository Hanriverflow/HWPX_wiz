HWPX_wiz,
이렇게 이해하면 쉽습니다.

복잡한 한글·Word 문서 작업을 “어떤 도구를 써야 하는지”부터 “실패했을 때 어디를 볼지”까지 한 흐름으로 정리한 실전용 HTML 가이드입니다.

Windows PowerShell Kordoc 4.13.1 Microsoft Word desktop Node.js / npm uv
가장 중요한 한 문장
HWPX_wiz는 문서를 보관하는 프로그램이 아니라, Kordoc·hwpx skill·Word 변환기를 상황에 맞게 연결하는 Windows용 통합 계층입니다.
따라서 먼저 “파일 형식 + 내가 하려는 일”을 판단하면 됩니다. 읽기/분석, HWPX 생성/편집, 구형 DOC 변환은 서로 다른 도구가 담당합니다.

03 · First Setup

처음 한 번만 하는 환경 설정

기준 예시 경로는 D:\Code\Projects\HWPX_wiz입니다. 실제 clone 경로가 다르면 바꾸면 됩니다.

저장소 루트로 이동 
Set-Location -LiteralPath "D:\Code\Projects\HWPX_wiz"
Python 환경 동기화

전역 pip 대신 uv.lock 기준으로 환경을 맞춥니다.

uv sync --locked
정상이면 .venv\Scripts\python.exe가 존재해야 합니다.
로컬 Kordoc CLI 설치 
npm ci --prefix .\tools\kordoc

node .\tools\kordoc\node_modules\kordoc\dist\cli.js --version
기준 버전은 4.13.1입니다.
검증 도구 설치 
Install-Module Pester -MinimumVersion 6.1.0 -Scope CurrentUser
Install-Module PSScriptAnalyzer -MinimumVersion 1.25.0 -Scope CurrentUser
Microsoft Word desktop 확인

구형 .doc 변환은 Windows의 Word.Application COM 자동화를 사용합니다. Word Online만으로는 안 됩니다.

Kordoc MCP와 hwpx skill 확인 
codex mcp list
Kordoc MCP는 저장소 lock과 같은 node.exe ...\kordoc\dist\cli.js mcp를 사용합니다.
Python 스크립트도 프로젝트 환경에서 실행 python script.py보다 uv run python .\path\to\script.py 형식을 권장합니다.
04 · Quick Start

가장 쉬운 사용법: inbox에 넣고 실행

파일을 하나하나 지정할 필요 없이 구형 .doc를 일괄 처리할 때 적합합니다.

A. DOCX만 만들기

1) .doc를 inbox에 복사

하위 폴더에 넣어도 검색합니다.

2) 배치 파일 실행 
.\convert-doc-to-docx.bat
3) 같은 폴더에서 결과 확인

보고서.doc → 보고서.docx

B. DOCX + Markdown 만들기

1) .doc를 inbox에 복사

원본은 그대로 보존됩니다.

2) 통합 배치 파일 실행 
.\convert-doc-to-md.bat
3) 결과 확인

보고서.doc + 보고서.docx + 보고서.md

이 명령은 기대한 대로 동작하지 않습니다. .\convert-doc-to-docx.bat "D:\문서"처럼 BAT 뒤에 경로를 줘도 그 경로는 무시됩니다. BAT는 항상 inbox만 처리합니다.
05 · Precision Mode

특정 파일·폴더만 변환하려면

.ps1 스크립트에 -Path를 직접 전달합니다.

특정 DOC 하나 → DOCX

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\tools\doc-to-docx\convert-doc-to-docx.ps1" `
  -Path "D:\문서\보고서.doc"

특정 DOC 하나 → DOCX + MD

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\tools\doc-to-docx\convert-doc-to-md.ps1" `
  -Path "D:\문서\보고서.doc"

폴더 바로 아래만

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\tools\doc-to-docx\convert-doc-to-docx.ps1" `
  -Path "D:\문서\구형자료"

-Recurse가 없으면 하위 폴더는 보지 않습니다.

하위 폴더까지 전부

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\tools\doc-to-docx\convert-doc-to-md.ps1" `
  -Path "D:\문서\구형자료" `
  -Recurse

옵션을 쉬운 말로

옵션언제 쓰나실무 해석
-Path항상“어느 파일/폴더를 처리할지” 지정
-Recurse폴더 + 하위 폴더까지“밑에 있는 폴더도 다 찾아봐”
-Overwrite기존 결과를 새로 만들 필요가 있을 때“기존 결과를 안전하게 교체해”
-LogPathDOC→DOCX 처리 로그 필요 시“처리 기록을 이 파일에 남겨”
-DocumentKey / -Password암호가 걸린 DOC“이 암호로 문서를 열어”
-KordocCliPath특수한 로컬 Kordoc 경로를 쓸 때만일반 사용에서는 생략 권장
경로에 공백·한글·&·괄호가 있으면? -Path "D:\문서\보고서 & 최종본.doc"처럼 큰따옴표로 감싸면 됩니다.
06 · Safety

-Overwrite가 생각보다 안전한 이유

이 도구는 기존 결과를 바로 덮어쓰는 방식이 아니라, 임시 파일과 복원 절차를 사용합니다.

1. Backup / Rollback기존 결과가 있으면 임시 백업
→
2. StagingGUID 기반 임시 DOCX/MD 생성
→
3. 전체 성공 확인모든 단계가 성공해야 다음 단계
→
4. 원자적 교체최종 파일로 교체 후 임시 파일 정리
실패하면 기존 DOCX/Markdown을 복원하고 새로 만든 중간 결과를 제거하도록 설계되어 있습니다.
그래도 예외는 있음 저장장치 오류, 권한 문제, 백신의 파일 잠금처럼 OS가 파일 교체 자체를 거부하면 잔류 파일과 오류 메시지를 확인해야 합니다.

Word 자동화도 안전 쪽으로 설정

✓문서를 읽기 전용으로 엽니다.
✓매크로 실행과 자동 링크 업데이트를 끕니다.
✓최종 DOCX는 변환 성공 전까지 교체하지 않습니다.
✓변환기가 소유한 Word 프로세스만 종료 대상으로 삼습니다.
✓원본 문서는 삭제하거나 덮어쓰지 않는 것이 기본 원칙입니다.
07 · Reading Results

실행 결과는 무엇을 보면 되나요?

복잡하게 볼 필요 없이 Status → Error → 종료 코드 순으로 보면 됩니다.

SUCCESS

Converted

실제로 새 결과가 만들어졌습니다.

NO CHANGE

Skipped

이미 결과가 최신이거나 처리할 필요가 없어 건너뛴 상태입니다.

CHECK

Failed

Error 메시지를 읽고 원인을 확인해야 합니다.

CONVERSION SUMMARY

  Skipped   : 0
  Failed    : 0

Reason건너뛴 이유
Error실패 원인

종료 코드 1Failed가 하나라도 있는 상태입니다.

10 · Verification

“제대로 설치됐나?” 확인하는 표준 명령

개발·정비 후에는 전체 검증, 평소에는 필요에 따라 사전조건만 검사하면 됩니다.

전체 검증

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\tools\verify.ps1"

마지막에 Repository verification passed.가 나오면 통과입니다.

사전조건만 빠르게

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\tools\verify.ps1" `
  -PrerequisiteCheckOnly

정상이면 Prerequisite check passed.가 나옵니다.

전체 검증에서 보는 것

환경

Pester, PSScriptAnalyzer, uv, Node.js/npm, Word COM

Kordoc

package, lockfile, CLI 존재 및 버전 4.13.1, npm dry-run

코드 품질

Pester 전체 테스트, ScriptAnalyzer, uv lock --check

검증기는 설치 프로그램이 아닙니다. 누락된 도구를 자동 설치하지 않습니다. 실패 메시지를 보고 필요한 준비를 한 뒤 다시 실행합니다.
11 · Optional Workflow

Herdr + OMO는 언제 필요한가?

문서 변환만 할 때는 필요 없습니다. 저장소 자체를 수정·개발·검증하는 멀티에이전트 작업 흐름이 필요할 때만 사용합니다.

PLAN / Sol무엇을 바꿀지 정의요구사항 + GOAL.md
→
BUILD / Luna구현 + 테스트AGENTS.md + GOAL.md 기반
→
VERIFY / Sol독립 검증diff · 테스트 · 요구사항 감사
핵심 문서 변환 자체는 Herdr/OMO 없이 PowerShell 명령만으로 완전히 실행할 수 있습니다.

HWPX_wiz는 다른 개발자가 만든 두 원본 프로젝트를 fork/기반으로 활용해 Windows 문서 작업의 사용성을 높인 통합 프로젝트입니다. HWPX_wiz가 원본 프로젝트의 저작자이거나 공식 배포본이라는 뜻은 아닙니다.

K

Kordoc 원본 프로젝트

원 저작자·유지보수자: chrisryugj/kordoc

HWP/HWPX/DOCX/PDF/XLSX의 읽기, 구조 추출, 비교와 변환을 담당합니다.

H

hwpx-skill 원본 프로젝트

원 저작자·유지보수자: jkf87/hwpx-skill

편집 가능한 HWPX 작성, 수정과 품질 검증을 담당합니다.

HWPX_wiz의 역할 각 upstream의 저작권·라이선스·원 저작자 표기를 존중하면서, 두 프로젝트를 Windows용 DOC 변환기, 검증 도구와 운영 문서로 통합해 사용성을 높입니다.
Source basis: USAGE_GUIDE.md의 운영 규칙과 명령을 초보자 관점에서 재구성한 설명 자료입니다. 원문의 안전 원칙과 명령 의미를 유지하되, 이해를 돕기 위해 순서와 표현을 단순화했습니다.
